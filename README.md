## 문제: 목표와 실행 사이의 '계획의 마찰'

2026년 8월, 성인 61명 대상 설문(편의표본) 결과:

| 지표 | 수치 |
|---|---|
| 목표를 세운 경험 | 93.4% (61명 중 57명) |
| 계획 단계에서 중단 | 75.4% |
| 목표 완료 전 중단 | 82.0% (끝까지 완료는 18.0%) |

계획을 끝내지 못한 이유 1위는 **"무엇을 해야 할지 쪼개는 방법을 모름"(48.9%)** 이었고,
완료 전 중단 이유 1위는 **"밀린 일정을 따라잡기 어려움"(45.9%)** 이었다. 즉 사람들은
목표를 못 세워서가 아니라, 목표를 실행 가능한 크기로 나누고 계속 이어가는 과정에서
멈춘다.

> 보고서의 "조사의 한계" 섹션도 함께 참고할 것 — 편의표본 61명 기준이라 전체 인구로
> 일반화할 수 없고, JustDO가 실제로 목표 달성률을 높인다는 인과관계도 아직 검증되지
> 않았다. 이번 조사는 "계획 단계의 마찰이 가장 크다"는 가설의 근거일 뿐이다.

## 해법: AI 계획 생성 × 게임형 진척도 × 목표 완료 경험

사용자는 목표와 실행에만 집중하고, AI가 계획을 구성한다.

```
사용자: 목표 한 문장 입력 (예: "10km 마라톤 완주")
   │
   ▼
AI: 추가 질문 (기간 · 현재 수준 · 가능한 요일)
   │
   ▼
AI: 날짜별 실행 작업으로 계획 초안 생성
   │
   ▼
사용자: 확인 · 수정 → 확정
   │
   ▼
매일 작업 완료 → 퍼즐 한 조각 지급 → 누적 결과가 랭킹으로 이어짐
```

- **AI 계획 생성** — 막연한 목표를 날짜 · 맥락 · 행동이 담긴 문장(예: "9월 3일 저녁, 집
  근처 공원에서 20분간 천천히 달린다")으로 쪼갠다. AI 초안은 사용자가 확인 · 수정한 뒤
  확정된다 — 자동화는 통제권을 빼앗는 게 아니라 부담을 줄이는 장치로 설계했다.
- **퍼즐 리워드** — 하루 한 작업 완료 = 퍼즐 한 조각. 진행 상황을 즉시 눈으로 보여준다.
- **랭킹** — 완성 퍼즐 수 · 지속 일수를 비교해 사회적 동기를 제공한다.
- **자동 리스케줄링**(다음 우선순위) — 일정이 밀려도 실패로 낙인찍지 않고, 남은 기간과
  작업량 기준으로 다시 분배한다. "밀린 일정을 따라잡기 어려움(45.9%)"에 가장 직접
  대응하는 기능이라 로드맵 1순위로 잡았다.

### 서비스 설계 원칙

1. 처음부터 완벽한 계획을 요구하지 않는다 — 짧은 질문으로 초안을 만들고, 대화로 수정한다.
2. 일정이 틀어지는 것을 정상으로 본다 — 미완료를 실패로 낙인찍지 않고 다시 분배한다.
3. 성취를 즉시 보이게 한다 — 작업 하나의 완료가 퍼즐 한 조각으로 바로 반영된다.
4. AI의 판단을 사용자에게 설명한다 — 왜 이 날짜와 작업량으로 배치했는지 확인할 수 있어야 한다.
5. 확정 전에는 사용자가 결정권을 가진다 — AI가 제안하고, 사용자가 수정 · 확정한다.

### 다음 검증 지표 (출시 후)

"사용했는가"가 아니라 "끝냈는가"를 본다 — 계획 확정률, 첫 작업 실행률, 7일 유지율,
리스케줄 회복률, 목표 완료율 순으로, 더 많은 할 일을 만드는 것보다 더 많은 목표를 끝내게
하는 것이 성공 기준이다. 자세한 지표 정의는 보고서 12쪽 참고.

## 아키텍처

세 레포(`ai`, `backend`, `frontend`)를 각각 팀원이 따로 개발하고, 제출 시점에 이 저장소
하나로 합쳤다(`git log` 참고 — `Add 'ai/' from commit ...` 형태의 커밋 3개).

```
frontend (React 19 + Vite + Tailwind)
        │  axios
        ▼
backend (Spring Boot + JPA + MySQL, S3)
        │  서버-서버 호출
        ▼
ai (FastAPI, 무상태 추론 서버)
```

| 디렉토리 | 스택 | 역할 |
|---|---|---|
| [`frontend/`](./frontend) | React 19, Vite, Tailwind CSS 4, react-router | 목표 입력, 채팅 UI, 퍼즐 · 랭킹 화면 |
| [`backend/`](./backend) | Spring Boot, Spring Data JPA, MySQL, AWS S3 | 인증, 캘린더/퍼즐/랭킹 상태 저장, AI 서비스 오케스트레이션 |
| [`ai/`](./ai) | FastAPI, Python | 목표 분석 · 계획 생성 · 수정 대화를 처리하는 무상태 LLM 추론 서버 |

각 서브디렉토리에 자체 `README.md`/`docs/`가 있다 — 로컬 실행 방법 등 세부 사항은 해당
디렉토리를 참고할 것:

- `ai/README.md` — AI 서비스 실행 방법, API(`/plan/generate`, `/plan/revise`, `/plan/confirm`)
- `backend/docs/` — [API 명세](<./backend/docs/API_SPECIFICATION_NOTION_최종.md>), [ERD](<./backend/docs/ERD_SPECIFICATION_최종.md>)
- `frontend/README.md` — 프론트엔드 실행 방법
