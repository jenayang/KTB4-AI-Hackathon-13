## 문제: 목표와 실행 사이의 '계획의 마찰'

2026년 8월, 성인 61명 대상 설문(편의표본, 5문항) 결과:

| 지표 | 수치 |
|---|---|
| 목표를 세운 경험 | 93.4% (61명 중 57명) |
| 계획 단계에서 중단 | 75.4% |
| 목표 완료 전 중단 | 82.0% (끝까지 완료는 18.0%) |

가장 큰 이탈 지점은 '계획 세우기'다 — 목표를 세운 경험은 흔하지만, 계획을 끝까지
완성한 비율은 4명 중 1명에도 미치지 못했다(24.6%). 따라서 단순한 목표 입력 기능보다
**'계획을 대신 구체화하는 기능'**이 먼저 필요하다는 것이 해석이다.

### 계획을 끝내지 못한 이유 (Q3, 응답 N=47)

| 이유 | 비율 |
|---|---|
| 무엇을 해야 할지 쪼개는 방법을 모름 | 48.9% (23명) |
| 계획 세우는 과정 자체가 귀찮음 | 27.7% |
| 계획대로 할 자신이 없음 | 12.8% |
| 계획할 시간이 없음 | 10.6% |

> 데이터 주의: Q2(계획 미완료)의 응답 인원은 46명이지만 Q3 응답은 47명으로, 분기 응답
> 수가 일치하지 않는다. 결과 해석에 이 점을 반영했다.

**제품으로 번역하면**: 사용자는 목표를 말하고, 서비스는 오늘의 작업으로 나눈다. AI
계획은 단순한 할 일 추천이 아니라, 막연한 목표를 날짜별 · 행동별로 구체화하는 역할을
맡는다. 핵심 질문은 "내일부터 무엇을 하면 되지?"에 한 화면 안에서 답할 수 있는가다.

### 완료 전 중단 — 언제, 왜 멈췄나

| 언제 멈췄나 | 비율 | 왜 멈췄나 | 비율 |
|---|---|---|---|
| 시작 전 | 13.1% | 밀린 일정을 따라잡기 어려움 | 45.9% |
| 3일 이내 | 14.8% | 점점 귀찮아짐 | 31.1% |
| 1~2주 | 26.2% | 성취감 없음 | 19.7% |
| 1개월+ | 27.9% | | |
| 완료 | 18.0% | | |

완료 전 중단의 핵심은 **일정이 어긋난 뒤 복구하기 어렵다는 점**이다. 그래서 가장 먼저
만들 기능으로 **자동 리스케줄링**을 선택했다 — 밀린 작업을 그대로 쌓아 두는 대신, 남은
기간과 작업량을 기준으로 다시 분배한다. 실패를 경고하는 서비스보다, 다시 시작할 수
있게 재구성하는 서비스가 되어야 한다는 것이 설계 방향이다.

## 사용자 경험 설계

기존 방식은 "목표 설정 → 계획 작성 → 일정 등록 → 실행 → 완료 판단"을 전부 사용자가
한다. JustDO는 "목표 입력(사용자) → AI 계획 생성(AI) → 오늘의 실행(사용자) → 퍼즐
완성(서비스)"으로 나눠, 계획 작성 · 등록의 부담을 AI가 맡고 사용자 행동 단계를 줄인다.

1. **목표 한 문장** — 예: "10km 마라톤 완주"
2. **추가 질문** — 기간 · 현재 수준 · 가능한 요일
3. **계획 초안** — 날짜별 실행 작업, 확인 · 수정 가능
4. **확정 후 실행** — 완료할 때마다 퍼즐 1조각

> 중요: AI 초안은 사용자가 확인 · 수정한 뒤 확정한다. 자동화는 통제권을 빼앗는 것이
> 아니라 부담을 줄이는 장치로 설계했다.

## 시장 포지셔닝

기존 서비스가 시간 배치 · 할 일 관리 · 인증에 강하다면, JustDO는 계획 생성부터 완료
판단까지 잇는다.

| 서비스 | 계획 자동화 | 실행 시각화 | 완료 판단 |
|---|:---:|:---:|:---:|
| Motion / Reclaim | ● | △ | — |
| Sunsama / Todoist | △ | △ | — |
| Challengers / 하루업 | — | ● | △ |
| **JustDO** | ● | ● | ● |

(● 강점 · △ 일부 지원 · — 핵심 기능 아님)

차별점은 '퍼즐' 자체가 아니다. 퍼즐은 실행 결과를 보여주는 표현 방식일 뿐이고, 핵심
차별점은 **AI가 계획을 만들고, 매일의 실행 기록을 모아 목표가 실제로 끝났는지 판단하는
전체 흐름**에 있다.

## 서비스 원칙

기능 수보다 "사용자가 계획을 시작하고 다시 이어 갈 수 있는지"가 중요하다는 기준으로
정리했다.

1. 처음부터 완벽한 계획을 요구하지 않는다 — 짧은 질문으로 초안을 만들고, 대화로 수정한다.
2. 일정이 틀어지는 것을 정상으로 본다 — 미완료를 실패로 낙인찍지 않고 다시 분배한다.
3. 성취를 즉시 보이게 한다 — 작업 하나의 완료가 퍼즐 한 조각으로 바로 반영된다.
4. AI의 판단을 사용자에게 설명한다 — 왜 이 날짜와 작업량으로 배치했는지 확인할 수 있어야 한다.
5. 확정 전에는 사용자가 결정권을 가진다 — AI가 제안하고, 사용자가 수정 · 확정한다.

## 이 조사로 말할 수 있는 것과 없는 것

좋은 기획 보고서는 강한 주장뿐 아니라 근거의 범위도 분명히 보여줘야 한다는 원칙으로
정리했다.

**말할 수 있는 것**
- 응답자 다수가 계획 단계에서 어려움을 경험했다.
- 작업 분해 방법을 모르는 문제가 가장 크다.
- 일정이 밀린 뒤 복구 어려움이 주요 중단 이유다.
- AI 계획 · 리스케줄링 가설을 검증할 근거가 있다.

**아직 말할 수 없는 것**
- 전체 성인 인구에 같은 비율이 적용된다는 주장.
- JustDO가 실제로 목표 달성률을 높인다는 인과관계.
- 모든 목표 카테고리에 같은 효과가 난다는 주장.
- 퍼즐 · 랭킹이 장기 사용을 보장한다는 주장.

**조사의 한계**
1. 편의표본 61명으로 대표성에 한계가 있다.
2. 응답 선택지를 연구자가 구성해 선택지 편향 가능성이 있다.
3. Q2와 Q3 응답 인원이 46명과 47명으로 일치하지 않는다.
4. 회상 기반 응답이므로 실제 행동 기록과 차이가 있을 수 있다.
5. 현재 근거만으로 서비스 효과의 인과관계를 판단할 수 없다.

## 다음 검증 지표 (출시 후)

서비스 가설을 실제 행동 데이터로 검증하기 위한 최소 지표. "사용했는가"가 아니라
"끝냈는가"를 본다.

| 순위 | 지표 | 정의 | 검증하는 것 |
|---|---|---|---|
| 1 | 계획 확정률 | 목표 입력 후 AI 계획을 확정한 비율 | 계획 생성이 실제 시작으로 이어지는가 |
| 2 | 첫 작업 실행률 | 확정 후 첫 작업을 완료한 비율 | 초안이 행동 가능한 수준인가 |
| 3 | 7일 유지율 | 첫 실행 후 7일 안에 다시 완료한 비율 | 퍼즐 피드백이 반복 행동을 돕는가 |
| 4 | 리스케줄 회복률 | 재분배 후 3일 내 작업을 완료한 비율 | 밀린 계획을 다시 이어 가게 하는가 |
| 5 | 목표 완료율 | 계획의 마지막 작업까지 끝낸 비율 | 서비스의 최종 가치가 실현되는가 |

**성공 기준**: 더 많은 할 일을 만드는 것보다, 더 많은 목표를 끝내게 하는 것.
